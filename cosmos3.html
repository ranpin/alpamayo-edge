摘要

本项目第二阶段（Phase W）把 NVIDIA Cosmos3-Edge（4B 全模态世界动作模型 = 2B VL reasoner + rectified-flow 扩散动作专家，MoT 单塔）部署到 Jetson Orin。它在 TRTEdge 0.10.1 官方支持矩阵里只属 Compatible 档（Official 是 JetPack 7.2 / CUDA 13 / TRT 11，而 Orin 是 JetPack 6.2 / CUDA 12.6 / TRT 10.7）——部署的代价是六道具体的兼容墙，本页记录逐道打通的过程与两条结果线。零预算 · 零训练 · 全 Orin。

两条结果线：

  1. Reasoner 侧——跨代验证「缩小模型不免费、量化几乎免费」：Cosmos3-Edge 的 2B VL reasoner 在自建驾驶域基准 n=184 上 42.4%（3.4× 随机基线），显著低于上一代 Cosmos-Reason2-8B 的量化版（INT4 50.5% / INT8 47.8%，McNemar b/c=29/12、p=0.0115）。新一代 2B 显著输给上一代 8B 的量化版——与主页结论 2 的"缩小不免费"在第二个模型家族上互证（§W.2）。
  2. Policy 侧——动作链部署打通，但单帧 turnkey 路径实测「帧无关」：DROID 动作链四组件引擎全部建成、cosmos3_policy_inference 冒烟通过（action [1,16,10] 全 finite、5154 ms/round）；但换输入帧输出几乎不变（跨帧 mean|Δ|≈0.009，比帧内自身位移小 ~170×）——这是 vision-only 单帧 conditioning 的能力边界，非引擎 bug（§W.3）。因此在线 demo 锚定已验证 works 且帧敏感的 reasoning 侧。

本页是 Phase W 专篇；第一阶段（CR2-8B 量化部署，图 1–21 / 表 1–13）见 CR2-8B 量化部署。问题、根因与解决的完整工程记录见 PROBLEMS.md §K/§L。

一、核心结果

W.1 部署：六道 JetPack 6.2 兼容墙与打通

TRTEdge 0.10.x 官方支持 Cosmos3-Edge，但 Orin 的 JetPack 6.2 只是 Compatible 档。实测代价 = 六道墙，各有工程解；其中两道同源（都是"TRT-11-only 算子墙"），用同一把自研武器解决。

三条教训
① Compatible 档的代价是具体、有限、可逐个击破的——六道墙各有工程解，不是"不支持"。② "上游不给预编译件"≠"不能生成"：构建脚本支持显式 target 覆盖，sm_87+cuda12 一次通过（K5）。③ 分解导出补丁是对「TRT-11-only 算子墙」的通用武器：K4（visual 的 TRT_Attention）与 K6（policy 的 ONNX Attention/RotaryEmbedding）同源同解；K6 是 policy 链唯一通路（gen 无 FMHA backend 可选）。

W.2 Reasoner 跨代对比：n=184 驾驶域（同帧同题，唯一变量 = 模型）

W.3 Policy 动作链：部署打通 + 单帧「帧无关」边界

Policy-DROID（nvidia/Cosmos3-Edge-Policy-DROID，机器人操作 WAM）四组件引擎全部建成，cosmos3_policy_inference 图+prompt→action.json 冒烟通过（goat）。第六道墙 K6 与打通见表 W1 与 §W.4。

冒烟结果（官方 UMI 首帧图 + "pick up the object"，4 步扩散）：exit=0，action shape [1,16,10]，160 值全 finite、范围 [−2.13, 2.77]，逐维分布有结构（d3≈−1.93±0.15、d5≈+2.15±0.14 紧聚类，非噪声）；延迟 5154 ms/policy round。

为何「预测 vs GT」对照不成立（表示动物园）
社区 lerobot/droid_100 GT 是 7 维笛卡尔 euler + lerobot 自归一化；Edge 输出是 10 维 midtrain rot6d + NVIDIA quantile 归一化；cosmos cookbook 的 droid 样例又是 8 维关节空间。三套表示 + 三套归一化 + 时间分辨率不同（policy 5fps vs GT 15fps）⇒ 四重错配，「对不上」是必然，非引擎错。拿 turnkey 输出比参考 GT 前，必须先核对表示 / 归一化 / state / 时间四者是否对齐。

二、方法细节（可复现）

W.4 分解注意力 / RoPE 导出补丁：对「TRT-11-only 算子墙」的通用武器

K4（visual）与 K6（policy）同源：TRTEdge 把注意力/RoPE 经 trt::attention_onnx/trt::rope_onnx custom op lower 成只有 TRT≥11 parser 认识的算子。解法 = 在导出前把它们用基础 ONNX 算子分解掉，任何 TRT 版本可解析，TRT 用 Myelin 自行融合：

  • decomposed_attention：GQA 折批 grouped matmul + arange 下三角 causal 掩码，覆盖 und 的 is_causal=True 自注意力与 gen 的 is_causal=False 对 cat([und,gen]) 的交叉注意力（GQA H=16/Hkv=8）。
  • decomposed_rope：rotate_half；attention_pos_id 是恒等 gather（cosmos3PolicyRunner.cpp:257）⇒ 逐 token 直接对齐，但仍用 torch.gather 保留 position_ids 防被 DCE 导致 runtime 找不到 binding。
  • 门控与对拍：env USE_DECOMPOSED_POLICY=1，两个 modeling 文件 import 换包装器（additive，不动已工作的 reasoning 路径）。分解实现先经 test_policy_decomposed.py 数值对拍（attention vs F.scaled_dot_product_attention err~1e-7、rope vs LLaMA 全维公式 err=0）再导出——避免 ~1h 导出后才发现语义 bug。脚本 scripts/orin/apply_policy_decomposed_patch.py。

W.5 动作表示 / 归一化 / state（cosmos-framework 权威定义）

  • 表示：Edge 用 midtrain 10 维 = [eef_pos(3) + rot6d(6) + gripper(1)]、相对位姿；后处理链 denormalize_action → pose_rel_to_abs（需当前 state 做参照）。
  • 归一化：quantile(q01/q99)→[−1,1]，stats 在 droid_lerobot_stats.json（dim0-2 位置 delta≈±0.015 米、dim3-8 rot6d、dim9 gripper[0,1]）；反归一化 0.5(a+1)(q99−q01)+q01。
  • state 注入定论：Edge 是 vision+language-only（gen 图 = 16 行、无 +1 state 行 ⇒ use_state=False）。TRTEdge PolicyRunner 把 action_latent 全填高斯噪声、mask 全 1、只注入 frame-0 图像 latent + und K/V，无本体状态——设计如此，非 bug。这正是 §W.3 帧无关的机理。

AV 行车轨迹另走 inverse-dynamics 模式（起始帧+视频→ego 轨迹，无需单独 AV policy 权重），但该模式仅 PyTorch 框架路径、非 turnkey，未 TRTEdge 化（列后续）。

三、思考讨论

跨代结论：「缩小不免费、量化几乎免费」在第二个模型家族上成立
第一阶段在 CR2-8B 上得到"量化几乎免费、2B 显著掉点"（主页结论 2）；Phase W 把同一把尺子（同帧同题 n=184）量到 Cosmos3-Edge：新一代 2B reasoner（42.4%）显著输给上一代 8B 的量化版（INT4 50.5% / INT8 47.8%）。两个独立模型家族同向 ⇒ 该结论不是 CR2 单家的偶然，强化了部署策略"激进量化 + 保留大模型"。
turnkey 工具的能力边界：测出边界并据实定位 > 假装能用
cosmos3_policy_inference 是简化路径——vision+language-only、单帧、无 state 锚点，与 cosmos-framework 参考 server（state-conditioned、多帧历史）输入契约不同。W2 冒烟是部署管线验证（分解引擎端到端跑通、产出结构合法动作），不是动作语义正确性验证；W3 换独立变量（帧）复测后把初判"原地抖动出不了动作"修正为"帧内有连贯位移、但帧无关"——结论从"模型坏"变成"单帧 conditioning 的能力边界"，方向完全不同。demo 因此锚定已验证 works 且帧敏感的 reasoning 侧，policy 动作链定位为「部署打通 + 帧无关边界」。

诚实的边界

  • Reasoner 侧：n=184 ⇒ MDE ≈ 7 pts，更小差异测不出；驾驶域标注是 clip 级事件聚类、train split 无法排除训练见过（同主页 §1.11 边界，对跨代对照不受影响）。
  • Policy 侧：冒烟只验管线跑通与输出格式，不验动作语义正确性；帧无关是 turnkey 单帧路径的边界，不代表 Cosmos3 policy 在 state-conditioned / 多帧参考实现下的能力。
  • 无 AV 轨迹输出：inverse-dynamics 仅 PyTorch、非 turnkey，未部署；ADE/FDE 属 VLA 轨道（主页结论 7）。
  • 帧必须缩到长边 448：原生 1920×1088 = 2040 token/帧，6 帧 12240 > 引擎 maxInputLen 2048 会失败；缩后与 n=184 同口径。
