Alpamayo-R1 轨迹预测 · 真实帧叠加

NVIDIA Alpamayo-R1（10B 自动驾驶 VLA）部署在 Jetson AGX Orin（TensorRT-Edge-LLM 三引擎），对真实驾驶片段输出 6.4 秒未来轨迹，与真值（GT）一起用该片段的鱼眼相机标定投影叠回原始前视相机画面；另含 4 段滚动预测视频（边前进边每 6s 重预测一次）。全部为 Orin 实机推理输出。

演示

两种形态、同一套叠加口径：GT 真值（绿）取自数据集 egomotion 标签、R1 FP16 预测（蓝实线）与 R1 INT4 预测（橙虚线）均为 Orin 实机推理输出（INT4 = AWQ 量化 backbone、visual/action 仍 FP16），三者都用该片段实测的鱼眼标定投影回前视相机原始帧，因此贴合实际路面。先看滚动预测视频（边前进边每 6s 重预测，4 场景），再看单次预测静态图（6 个困难转弯片段的精度谱）。

滚动预测视频（边前进边预测）：以下 4 段视频里 R1 每 6 秒重新预测一次——这是它在 Orin 上的实测单次推理耗时（FP16 稳态 ~5.3s，非人为缩短的间隔），每段 3 个锚点（t₀=1.5 / 7.5 / 13.5s）。绿 GT、蓝 R1 FP16、橙虚线 R1 INT4 同锚 t₀（同窗 [t₀, t₀+6.4]s，重叠=预测精度），随车前进被一起「吃掉」、到下个锚点一起刷新；HUD 常显实时车速与「单次推理 FP16 ~5.7s / INT4 ~4.2s · 事件级非实时」，信息行标注本段 FP16/INT4 的 ADE@6.4s，刷新瞬间黄色高亮。4 段总览见图 1，逐锚点误差与口径见「评测结果」表 2。

评测结果

测试数据集：NVIDIA PhysicalAI-AV 数据集 dgural 公开 sample 的 6 个 clip——前视广角相机真实帧 + ~100Hz egomotion GT 轨迹；6 个片段均为「6.4s 预测窗内明显转弯」的困难样本（非随机抽样，见下方「口径与诚实边界」）。推理口径：Alpamayo-R1（TRTEdge FP16）Jetson Orin 实机、单噪声种子（seed=5、temperature=0）确定性推理，无训练微调。

下表为 6 个片段上 R1 FP16 与 INT4（AWQ 量化）预测相对 GT 的逐点欧氏位移误差（ego 系，按 FP16 ADE@6.4s 升序）。核心观察：R1 的思维链与其轨迹精度强相关——当 CoT 正确识别出机动（如「绿灯左转」「并入右转道」）时轨迹几乎完美贴合（ADE 低至 0.84m）；当 CoT 退化为泛化的「跟前车」时，模型会漏判或欠判即将到来的转弯（最差例蓝线直冲、绿线左拐，ADE 5.90m）。INT4 与 FP16 逐片段互有高低、整体同量级（6 片段平均 ADE@6.4s FP16 3.10m / INT4 3.41m），印证「量化近乎免费」。

误差公式：ADE@T（平均位移误差）= 预测与 GT 在前 T 秒每个 waypoint 上欧氏距离的均值 = (1/N)·Σᵢ‖predᵢ − gtᵢ‖；FDE@T（终点位移误差）= 第 T 秒末 waypoint 的欧氏距离 = ‖pred_N − gt_N‖。@3s 取前 30 点、@6.4s 取全部 64 点（10 Hz）；均在 t₀ 时刻 ego 系（自车为原点、x 前 y 左）计算，单位米。
口径与诚实边界：① 单噪声种子（seed=5、temperature=0）确定性推理，非官方 minADE6（6 采样取最优）；② 6 个片段均为「6.4s 预测窗内明显转弯」的困难样本、非随机抽样，误差天然高于官方全集；③ 数据源 dgural 公开样本的 README 明确声明「不适合 benchmarking / 统计分析」——本页数字仅为逐例行为展示，不构成代表性精度结论；④ 官方 Alpamayo-R1 在 644 clip 上报告 minADE6@6.4s≈0.79m，口径不同，不可与本表直接比较。

滚动口径（表 2）：表 1 回答「困难片段上的单次预测精度」，表 2 回答「滚动设定下的逐锚点精度」——4 个片段（直行跟车 0dd3eb7f / 左转·红灯起停 ecafce84 / 右转 1fcf2fef / 变道 1f7ef408，前视广角真实帧各 ~20s）× 3 锚点（t₀=1.5/7.5/13.5s）= 12 条预测，每 6s 重预测一次（=实测单次推理耗时），同一 Orin 实机、每锚点单样本（temperature=0）、开环 6.4s、无导航输入。列集与表 1 不同：滚动版补「终点纵/横差」与「误差形态」两列，用于定位「几米偏移」的构成；终点差 = pred−gt（t₀ ego 系，纵向 + = 过伸、横向 + = 偏左）。

核心方法

输入 / 数据 模型推理 硬件 / 部署 轨迹后处理 输出 / 结果 问题 / 补丁

图 12 · Alpamayo-R1 的 Orin 推理链：16 帧 + ego 历史 → visual / llm / action 三引擎（分解注意力补丁打穿 TRT≥11 算子墙）→ CoT 与轨迹 token → 自行车积分 → BEV 轨迹 → 鱼眼标定投影叠加

  • 模型：Alpamayo-R1 = VLM backbone（Qwen3-VL 8B）+ 扩散动作专家（2.3B），单次推理同时产出思维链文本与动作头输出。
  • 输入：4 路相机（cross_left / front_wide / cross_right / front_tele）× 4 个历史时刻（t₀−0.3…t₀）共 16 帧 + 16 点 ego 历史轨迹。
  • 输出：思维链（CoT）文本 + output_trajectory [64,2]（归一化 accel, κ）；动作头输出积分后得 BEV 轨迹（见下「轨迹积分」）。
  • 边缘部署：TensorRT-Edge-LLM 三引擎（llm / visual / action）建于 Jetson AGX Orin（sm_87 / JetPack 6.2）。action 专家的 Attention/RotaryEmbedding/TensorScatter 算子需 TRT≥11，用分解注意力补丁打穿该墙（Orin 的 TRT 10.7 不原生支持）。
  • 轨迹积分：动作头输出经运动学自行车模型积分得 BEV 轨迹（6.4s / 64 点 / 10Hz）；初速 v₀ 由 ego 历史经官方 compute_minade 的最小二乘（Cholesky）反解，与 minADE 评测同一套后处理口径。
  • 投影叠加：GT 与 R1 轨迹均用该片段实测的鱼眼相机标定（多项式畸变 fw_poly + 四元数外参）投影回前视图像；GT 带真实路面高程 z，R1 的 2D 输出按 GT 路面高程插值赋 z，使两者都贴合路面。
  • 滚动视频版：每锚点 t₀ 用同上的输入/输出跑一次完整推理；GT 与预测轨迹世界锚定在 t₀（同窗对比，重叠=精度），再按每帧自车位姿（egomotion 全四元数）重投影回前视画面——轨迹随车前进被「吃掉」、每 6s（=实测单次推理耗时）一起刷新；HUD 叠加实时车速（egomotion vx/vy/vz 真值）、本段 ADE@6.4s 与「事件级非实时」标注。复现脚本见 eval/r1/dgural_demo/（README 含管线与逐锚点误差表）。
  • 数据来源：图像帧取自 dgural 公开样本（NVIDIA PhysicalAI-AV 的公开 100-clip 子集）；GT 轨迹与相机标定取自 gated NVIDIA PhysicalAI-AV；帧↔egomotion 时间对齐用数据集自带的逐帧时间戳权威校准（非按 fps 推算）。
